# 知序生产部署与运维手册

本文是当前项目生产运行的权威说明。课程维护和本地开发仍以根目录 `README.md` 为准。

> 核对日期：2026-09-06；依据为仓库中的 Compose、Dockerfile、Nginx、Django 配置及发布/备份/恢复脚本。下列操作说明不表示已在本轮执行容器部署、TLS 或恢复演练。

## 1. 运行架构

```text
公网 HTTPS 入口
  └─ 127.0.0.1:8080 前端 Nginx
       ├─ Vue 静态资源
       ├─ /api、/admin、/static → Django/Gunicorn
       └─ /protected-media → 只读媒体目录（仅 X-Accel-Redirect）
                                  ├─ MySQL 8.4
                                  ├─ Redis 7.4（认证、验证码、限流）
                                  └─ 可选 AI Redis（上下文、临时附件、请求锁）
```

Compose 不直接把数据库、Redis或后端端口发布到公网。入口层必须终止 TLS，并把 `X-Forwarded-Proto` 设置为原始协议。

## 2. 首次部署

1. 安装 Docker Engine、Compose v2、`bash`、`gzip`、`tar` 和 `sha256sum`。
2. 复制 `.env.example` 为 `.env`，只填写域名、邮件和非敏感参数。
   小范围朋友使用时保持 `INVITE_ONLY_REGISTRATION=1`；先由已有账号创建学习小队，再将可轮换邀请码交给新成员。匿名用户必须先通过邀请码校验，系统才会发送注册验证码。
3. 按 `secrets/README.md` 创建密钥文件，执行 `chmod 700 secrets && chmod 444 secrets/*`；目录阻止其他主机账号访问，文件只读权限供不同的非 root 容器用户读取。
4. 创建 `backend/media`，执行 `sudo chown -R 10001:10001 backend/media`。
5. 在入口层申请并自动续期 TLS 证书，把正式域名转发到 `127.0.0.1:8080`。
6. 执行 `bash deployment/deploy.sh`，确认 `/api/health/live/` 与 `/api/health/ready/` 都返回 200。
7. 创建管理员并完成注册、登录、刷新、退出、课程学习、图片上传和管理员审核冒烟测试。
8. 如需 AI，先按第 7 节小范围启用，再使用真实但低权限/低额度的测试 Key 验证文字、图片、PDF、超时、删除会话和关闭开关；不要使用生产主账号 Key 做冒烟。

生产环境缺少密钥、非默认数据库密码、正式域名、HTTPS 或可信 CSRF 来源时，Django 会直接拒绝启动。

首次管理员可在服务就绪后创建：

```bash
docker compose exec backend python manage.py createsuperuser
docker compose exec backend python manage.py showmigrations learning
```

邀请注册开启而尚无普通账号时，可先用已创建的管理员登录前端，创建小队并获取邀请码。前端管理中心为 `/admin/reviews`，Django 数据维护后台为 `/admin/`；两者不是同一页面。

### 配置来源与关键参数

Compose 从根 `.env` 插值，只把配置中列出的变量注入容器；在 `.env` 增加一个未被 Compose 引用的变量，不会自动传给 Django。直接运行 `manage.py` 则读取当前进程环境，不会自行加载 `.env`。支持 `_setting` 的敏感参数先读 `*_FILE` 指向的文件，再考虑普通环境变量，文件不可读会停止启动。

| 参数 | 当前默认 / 约束 | 用途 |
|---|---|---|
| `DJANGO_ALLOWED_HOSTS` | Compose 必填，逗号分隔 | 不含协议的域名白名单 |
| `CSRF_TRUSTED_ORIGINS` | Compose 必填 | 含 `https://` 的可信来源，与公网入口一致 |
| `APP_BIND_ADDRESS` / `APP_PORT` | `127.0.0.1` / `8080` | 前端主机监听位置；只由可信 TLS 入口转发 |
| `MYSQL_DATABASE` / `MYSQL_USER` | `zhixu` / `zhixu` | 应用数据库和账号，密码来自 secret |
| `INVITE_ONLY_REGISTRATION` | Compose 默认 `1`；Django 裸开发默认 `0` | 控制匿名注册验证码是否要求有效邀请码 |
| `MEDIA_URL_TTL_SECONDS` | `600` 秒 | 已授权页面签发的附件链接有效期 |
| `AI_ASSISTANT_ENABLED` | Compose 默认 `0` | AI 写入、会话历史及凭据接口的总开关 |
| `AI_CREDENTIAL_ENCRYPTION_KEY_FILE` | AI 附加配置注入 | 解密用户已保存供应商 Key，需独立备份 |
| `AI_CUSTOM_ALLOWED_HOSTS` | 空值表示不另加域名白名单 | 不取消公网 HTTPS、DNS 和重定向检查 |
| `AI_REQUEST_TIMEOUT_SECONDS` | 默认 `45`，代码限制 `5～50` 秒 | 同步供应商请求时间上限 |
| `AI_ATTACHMENT_MAX_FILES` / `AI_ATTACHMENT_MAX_BYTES` | 默认 `2` / `4194304`（4 MiB） | AI 单次文件数和每个文件大小，区别于学习证据上传 |
| `AI_ATTACHMENT_TEXT_MAX_CHARS` / `AI_PDF_MAX_PAGES` | 默认 `12000` / `20` | 文本提取长度及 PDF 页数 |
| `AI_ATTACHMENT_CACHE_TTL_SECONDS` | 默认 `3600` 秒 | 临时附件上下文的最长缓存时间，可提前被淘汰 |
| `AI_CONTEXT_CACHE_TTL_SECONDS` | 默认 `900` 秒 | 最近文字上下文缓存时间 |

完整可注入项以 [`docker-compose.yml`](../docker-compose.yml) 和 [`.env.example`](../.env.example) 为准；上下限以 [`settings.py`](../backend/config/settings.py) 为准。镜像当前使用 Python 3.13、Node.js 24 构建前端、MySQL 8.4 和 Redis 7.4；仓库中的供应商模型名是配置默认值，不证明对应供应商账号当前可用。

## 3. 发布与回滚

`deployment/deploy.sh` 依次执行现网备份、镜像构建、数据库和 Redis 就绪、独立迁移/课程导入/静态收集、Web 服务更新与就绪检查。迁移不会在 Web 容器重启时自动运行。

每次发布前记录当前镜像标识并保留最近一次可恢复备份。应用代码需要回滚时恢复旧镜像；如果迁移包含不兼容的数据变更，使用已验证的备份恢复，而不是删除 MySQL 卷。课程导入会跳过管理员在线修改过的学习日，除非显式使用 `--force`。

当前脚本没有自动版本标记或失败后自动回滚。`deploy.sh` 仅在检测到数据库容器运行时自动调用备份；已停止的旧数据库需先恢复可备份状态并确认备份完成。`release` 的迁移、课程导入、静态收集命令在 Compose 内定义，不存在独立 `deployment/release.sh`。

### 学习增强版本升级

1. 保存旧镜像标识、数据库与媒体备份，以及匹配的 AI 主密钥。
2. 核对发布代码包含 `0017_learning_practice_and_showcase`。此迁移只新增接续提示、作答快照和精选标记，不修改课程 JSON。
3. 执行发布脚本。常规 release 仍会按既定流程导入系统课程，在线人工编辑日默认跳过；不要为了启用固定题目额外强制覆盖课程。
4. 用 `showmigrations learning` 确认 `0017`，验证学习页保存、展柜、复习和导出；前端需与后端一并更新。
5. 两名测试成员分别提交接力分工，确认成员能读所选证据、无关用户不能读取；媒体需经过生产 Nginx 验证。

恢复旧代码与把数据库反向迁移到 `0016` 是两件事；后者会删除三个新增字段中的数据。代码回滚前先检查兼容性，数据回滚按已验证的备份流程执行。

## 4. 备份与恢复

可按日安排 `BACKUP_DIR=/安全挂载点 bash deployment/backup.sh`；脚本本身不创建定时任务、保留策略或异地同步。每个备份包含压缩数据库、压缩媒体文件和 SHA-256 校验和。备份目录必须加密同步到另一台机器或对象存储，并设置独立访问凭据；只保存在同一云盘不算灾难恢复。

恢复前在隔离环境执行：

```bash
# 将这两个占位值替换为实际备份目录名和绝对路径。
RESTORE_CONFIRM='备份目录名' bash deployment/restore.sh '/安全挂载点/备份目录名'
```

脚本会先校验输入备份、备份当前状态、停止 Web，再恢复数据库和媒体、执行当前 release 并等待服务健康；原媒体目录会保留为带时间戳的回退副本。首次上线和以后每季度至少完成一次隔离恢复演练并记录耗时。建议目标：数据库和媒体最多损失 24 小时数据，严重故障 4 小时内恢复；业务规模增长后再收紧指标。

恢复会删除并重建配置中的整个应用数据库，因此必须先确认 Compose 项目、数据库名、备份日期和恢复目标；`RESTORE_CONFIRM` 只是防误触确认，不提供自动环境隔离。恢复后运行的是**当前代码**的 release，包含课程导入和迁移，不是仅解压一个历史快照。

当前 `SHA256SUMS` 记录备份生成时的绝对文件路径。异地演练时，应将已验证备份放回相同的绝对目录，再运行校验和恢复；不要在原主机用旧路径的校验结果证明另一份副本完整，也不要通过重新生成校验和跳过损坏检查。这是现有脚本的可移植性限制。

备份脚本不包含 `.env`、`secrets/*`、镜像、AI Redis 或浏览器草稿。特别是 AI Fernet 主密钥，必须通过独立的加密秘密备份渠道保存；只有 MySQL 密文而没有匹配主密钥，无法恢复用户保存的供应商 Key。网站 Markdown/JSON 学习导出只用于阅读或整理个人学习记录，不能代替灾难恢复备份。

## 5. 监控与日志

- 存活探针只检查 Web 进程；就绪探针同时检查 MySQL 和 Redis。
- 收集 Nginx、Gunicorn 标准输出和 Django `django.request`、`django.security`、`learning.audit` 日志。
- 日志包含请求编号、用户编号、方法、路径、状态和耗时，不记录密码、令牌、验证码、正文和附件内容。
- 至少为连续 5xx、就绪失败、容器重启、磁盘超过 80%、备份失败、证书即将过期和登录异常峰值设置告警。
- AI 开启后增加供应商 401/429/5xx、请求超时、同步 Worker 饱和、AI Redis 内存/淘汰次数告警；监控只记状态、耗时、用户编号和供应商，不记 Key、问题、回复或附件正文。
- 每天执行 `docker compose run --rm backend python manage.py flushexpiredtokens` 清理过期令牌记录。

## 6. 安全操作

- 密钥只通过 Docker secrets 提供；怀疑泄露时轮换 Django、数据库和邮件凭据。
- HSTS 从 1 小时逐步提高，确认所有子域永久 HTTPS 后才启用 `INCLUDE_SUBDOMAINS` 和 `PRELOAD`。
- 管理员账号不与普通学习账号共用，定期检查 `learning.audit` 和 Django Admin 日志。
- 用户上传只允许当前白名单格式；新增格式前必须同时评估内容嗅探、浏览器内联执行和恶意文件扫描。
- AI 文件只支持 JPEG/PNG/WebP、PDF、文本和常见源码；图片会重新编码并去除 EXIF，PDF/文本限页限字，文件本体不写入 media 或 MySQL。较大请求可能短暂进入后端 `/tmp`，该目录已由 tmpfs 承载，请求结束后清理。
- 逆向与采集课程只允许本人资产、专用靶场或明确授权样本，不上传真实凭据和第三方用户数据。

## 7. AI 开启、隔离与故障关闭

生产默认 `AI_ASSISTANT_ENABLED=0`。仅开放临时 Key 时，把 `.env` 中该值改为 `1` 后按正常流程发布；临时 Key 不写数据库、Redis、Cookie 或浏览器持久存储。全局助手允许用户填写模型 HTTPS 接口，应用会拒绝本机、内网、保留地址、内嵌凭据和重定向；生产环境建议同时设置逗号分隔的 `AI_CUSTOM_ALLOWED_HOSTS`，只放行实际使用的供应商域名。

需要“记住 Key”时，创建 `secrets/ai_credential_encryption_key`，并使用附加 Compose 文件部署：

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())" > secrets/ai_credential_encryption_key
chmod 444 secrets/ai_credential_encryption_key
COMPOSE_FILE=docker-compose.yml:docker-compose.ai.yml bash deployment/deploy.sh
```

附加文件同时启动 128MB、无持久化、`allkeys-lru` 的独立 AI Redis，避免较大的图片上下文挤掉认证验证码与限流状态。MySQL 仍是文字会话的权威来源；Redis 重启或淘汰只会失去最近文本加速和附件后续轮次能力。容量提高前先观察命中率、内存与淘汰次数，不能把“使用 Redis”理解为不占存储。

主密钥轮换会使旧密文不可解密。操作顺序是：关闭 AI 并重新发布使开关生效、替换主密钥、再次发布、在重新开启后通知用户删除旧配置并重新保存 Key。上游异常时先关闭开关，原有学习 API、进度、证据与小队功能无需回滚。关闭期间除供应商目录返回 `enabled=false` 外，受 AI 开关保护的凭据、会话读取和删除也返回 404；已有 MySQL 记录不会自动删除，需重新开启后才能使用这些接口管理历史。

修改 Compose 环境变量后应重新创建对应服务，单纯 `docker compose restart` 不会重新注入新的环境值。启用 AI 附加文件后，后续发布、备份、恢复及管理命令应沿用同一组合，例如在 Linux shell 中先设置：

```bash
export COMPOSE_FILE=docker-compose.yml:docker-compose.ai.yml
```

附加文件负责主密钥与独立缓存，并不会自动把 `AI_ASSISTANT_ENABLED` 改为 `1`，开关仍由根 `.env` 控制。

`AI_OPENAI_MODELS` 和 `AI_ANTHROPIC_MODELS` 只维护旧版固定官方接口会话；新建全局会话接受 Base URL 或完整端点，并把规范化后的协议、最终请求地址和模型保存在会话快照中。应用会在保存和每次调用前重新解析域名，但应用层 DNS 校验无法单独消除 DNS 重绑定，因此生产网络仍须限制后端容器访问云元数据、本机和内网管理网段，并按需限制只可访问 443 端口。当前调用为同步非流式，只有监控证明 3 个 Gunicorn Worker 经常被占满时才评估独立 Worker 或 SSE。

## 8. 上线门禁

- CI 全部通过，迁移没有遗漏，生产 `check --deploy` 没有未解释警告。
- 正式域名 HTTPS、CSRF、CSP、安全 Cookie 和接口限流已实测。
- 备份已同步异地，并完成一次从备份恢复后的完整登录学习验证。
- 停止 MySQL、停止 Redis和模拟邮件服务超时时，告警与降级符合预期。
- AI 开启时验证：其他用户会话不可读、供应商失败不产生半条历史、不改变学习完成状态、附件过期可安全降级、关闭开关后原流程仍正常。
- 明确隐私联系渠道、社区举报处理人、事故联系人和维护窗口。

任何一项未完成，都应继续保持内测或受控访问，不开放公网注册。

## 9. 常见故障排查

| 现象 | 核对顺序 |
|---|---|
| 后端启动即拒绝生产配置 | `DJANGO_ENV/DEBUG/SECURE_SSL`、正式域名、CSRF 来源、secret 文件可读性；不要打印密钥内容 |
| `live` 正常但 `ready` 失败 | MySQL 健康状态、账号权限、Redis 连接及缓存读写；`ready` 只检验默认缓存，不证明独立 AI Redis 正常 |
| 登录或写入返回 CSRF 403 | 入口是否保留正确 Host 和原始 HTTPS 协议、浏览器 Cookie、可信来源是否一致 |
| 新页面提示字段不存在 | 目标数据库是否应用 `0017`，是否混用了旧后端、新前端或错误数据库 |
| AI 404 | 先读供应商目录 `enabled`，核对开关和服务是否重新创建，再检查会话所有权 |
| 无法保存模型配置或旧 Key 无法解密 | 独立 Fernet 主密钥是否缺失、变更或与数据库不匹配 |
| 附件请求成功但内容为空 | 生产 Django 返回 `X-Accel-Redirect`，需从前端 Nginx 路径访问；核对共享 media 挂载和 internal location |
| 附件提示链接过期 | 重新打开有权限的业务页面，签名不会无限续期；已退出小队者不能再获取新链接 |
| 学习证据上传失败 | 前端压缩/格式、后端证据限制、Nginx 12 MiB 请求上限；不能套用 AI 附件的单文件限制 |
| 发布停在课程导入 | 阅读具体日编号与人工修改/用户关联记录提示；先迁移关联数据，不用 `--force` 绕过删除保护 |

排查时只保留请求编号、时间、状态码和脱敏错误。需要分享配置时先移除密钥、Cookie、签名附件地址和私人正文。
