# 知序生产部署与运维手册

本文是当前项目生产运行的权威说明。课程维护和本地开发仍以根目录 `README.md` 为准。

## 1. 运行架构

```text
公网 HTTPS 入口
  └─ 127.0.0.1:8080 前端 Nginx
       ├─ Vue 静态资源
       ├─ /api、/admin、/static → Django/Gunicorn
       └─ /protected-media → 只读媒体目录（仅 X-Accel-Redirect）
                                  ├─ MySQL 8.4
                                  ├─ Redis 7.4（认证、验证码、限流）
                                  └─ 可选 AI Redis（上下文、临时附件、请求锁）
```

Compose 不直接把数据库、Redis或后端端口发布到公网。入口层必须终止 TLS，并把 `X-Forwarded-Proto` 设置为原始协议。

## 2. 首次部署

1. 安装 Docker Engine、Compose v2、`bash`、`gzip`、`tar` 和 `sha256sum`。
2. 复制 `.env.example` 为 `.env`，只填写域名、邮件和非敏感参数。
   小范围朋友使用时保持 `INVITE_ONLY_REGISTRATION=1`；先由已有账号创建学习小队，再将可轮换邀请码交给新成员。匿名用户必须先通过邀请码校验，系统才会发送注册验证码。
3. 按 `secrets/README.md` 创建密钥文件，执行 `chmod 700 secrets && chmod 444 secrets/*`；目录阻止其他主机账号访问，文件只读权限供不同的非 root 容器用户读取。
4. 创建 `backend/media`，执行 `sudo chown -R 10001:10001 backend/media`。
5. 在入口层申请并自动续期 TLS 证书，把正式域名转发到 `127.0.0.1:8080`。
6. 执行 `bash deployment/deploy.sh`，确认 `/api/health/live/` 与 `/api/health/ready/` 都返回 200。
7. 创建管理员并完成注册、登录、刷新、退出、课程学习、图片上传和管理员审核冒烟测试。
8. 如需 AI，先按第 7 节小范围启用，再使用真实但低权限/低额度的测试 Key 验证文字、图片、PDF、超时、删除会话和关闭开关；不要使用生产主账号 Key 做冒烟。

生产环境缺少密钥、非默认数据库密码、正式域名、HTTPS 或可信 CSRF 来源时，Django 会直接拒绝启动。

## 3. 发布与回滚

`deployment/deploy.sh` 依次执行现网备份、镜像构建、数据库和 Redis 就绪、独立迁移/课程导入/静态收集、Web 服务更新与就绪检查。迁移不会在 Web 容器重启时自动运行。

每次发布前记录当前镜像标识并保留最近一次可恢复备份。应用代码需要回滚时恢复旧镜像；如果迁移包含不兼容的数据变更，使用已验证的备份恢复，而不是删除 MySQL 卷。课程导入会跳过管理员在线修改过的学习日，除非显式使用 `--force`。

## 4. 备份与恢复

每天使用 `BACKUP_DIR=/安全挂载点 bash deployment/backup.sh`。每个备份包含压缩数据库、压缩媒体文件和 SHA-256 校验和。备份目录必须加密同步到另一台机器或对象存储，并设置独立访问凭据；只保存在同一云盘不算灾难恢复。

恢复前在隔离环境执行：

```bash
RESTORE_CONFIRM=<备份目录名> bash deployment/restore.sh <备份目录>
```

脚本会先备份当前状态、停止 Web、校验文件、恢复数据库和媒体、执行当前迁移并重新检查服务；原媒体目录会保留为带时间戳的回退副本。首次上线和以后每季度至少完成一次隔离恢复演练并记录耗时。建议目标：数据库和媒体最多损失 24 小时数据，严重故障 4 小时内恢复；业务规模增长后再收紧指标。

## 5. 监控与日志

- 存活探针只检查 Web 进程；就绪探针同时检查 MySQL 和 Redis。
- 收集 Nginx、Gunicorn 标准输出和 Django `django.request`、`django.security`、`learning.audit` 日志。
- 日志包含请求编号、用户编号、方法、路径、状态和耗时，不记录密码、令牌、验证码、正文和附件内容。
- 至少为连续 5xx、就绪失败、容器重启、磁盘超过 80%、备份失败、证书即将过期和登录异常峰值设置告警。
- AI 开启后增加供应商 401/429/5xx、请求超时、同步 Worker 饱和、AI Redis 内存/淘汰次数告警；监控只记状态、耗时、用户编号和供应商，不记 Key、问题、回复或附件正文。
- 每天执行 `docker compose run --rm backend python manage.py flushexpiredtokens` 清理过期令牌记录。

## 6. 安全操作

- 密钥只通过 Docker secrets 提供；怀疑泄露时轮换 Django、数据库和邮件凭据。
- HSTS 从 1 小时逐步提高，确认所有子域永久 HTTPS 后才启用 `INCLUDE_SUBDOMAINS` 和 `PRELOAD`。
- 管理员账号不与普通学习账号共用，定期检查 `learning.audit` 和 Django Admin 日志。
- 用户上传只允许当前白名单格式；新增格式前必须同时评估内容嗅探、浏览器内联执行和恶意文件扫描。
- AI 文件只支持 JPEG/PNG/WebP、PDF、文本和常见源码；图片会重新编码并去除 EXIF，PDF/文本限页限字，文件本体不写入 media 或 MySQL。较大请求可能短暂进入后端 `/tmp`，该目录已由 tmpfs 承载，请求结束后清理。
- 逆向与采集课程只允许本人资产、专用靶场或明确授权样本，不上传真实凭据和第三方用户数据。

## 7. AI 开启、隔离与故障关闭

生产默认 `AI_ASSISTANT_ENABLED=0`。仅开放临时 Key 时，把 `.env` 中该值改为 `1` 后按正常流程发布；临时 Key 不写数据库、Redis、Cookie 或浏览器持久存储。全局助手允许用户填写模型 HTTPS 接口，应用会拒绝本机、内网、保留地址、内嵌凭据和重定向；生产环境建议同时设置逗号分隔的 `AI_CUSTOM_ALLOWED_HOSTS`，只放行实际使用的供应商域名。

需要“记住 Key”时，创建 `secrets/ai_credential_encryption_key`，并使用附加 Compose 文件部署：

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())" > secrets/ai_credential_encryption_key
chmod 444 secrets/ai_credential_encryption_key
COMPOSE_FILE=docker-compose.yml:docker-compose.ai.yml bash deployment/deploy.sh
```

附加文件同时启动 128MB、无持久化、`allkeys-lru` 的独立 AI Redis，避免较大的图片上下文挤掉认证验证码与限流状态。MySQL 仍是文字会话的权威来源；Redis 重启或淘汰只会失去最近文本加速和附件后续轮次能力。容量提高前先观察命中率、内存与淘汰次数，不能把“使用 Redis”理解为不占存储。

主密钥轮换会使旧密文不可解密。操作顺序是：设置 `AI_ASSISTANT_ENABLED=0` 并重启、替换主密钥、再次发布、通知用户删除旧 Key 后重新保存。上游异常时先关闭开关，原有学习 API、进度、证据与小队功能无需回滚；已保存的会话文字仍可删除，但 AI 接口在关闭期间返回不可用。

`AI_OPENAI_MODELS` 和 `AI_ANTHROPIC_MODELS` 只维护旧版固定官方接口会话；新建全局会话接受 Base URL 或完整端点，并把规范化后的协议、最终请求地址和模型保存在会话快照中。应用会在保存和每次调用前重新解析域名，但应用层 DNS 校验无法单独消除 DNS 重绑定，因此生产网络仍须限制后端容器访问云元数据、本机和内网管理网段，并按需限制只可访问 443 端口。当前调用为同步非流式，只有监控证明 3 个 Gunicorn Worker 经常被占满时才评估独立 Worker 或 SSE。

## 8. 上线门禁

- CI 全部通过，迁移没有遗漏，生产 `check --deploy` 没有未解释警告。
- 正式域名 HTTPS、CSRF、CSP、安全 Cookie 和接口限流已实测。
- 备份已同步异地，并完成一次从备份恢复后的完整登录学习验证。
- 停止 MySQL、停止 Redis和模拟邮件服务超时时，告警与降级符合预期。
- AI 开启时验证：其他用户会话不可读、供应商失败不产生半条历史、不改变学习完成状态、附件过期可安全降级、关闭开关后原流程仍正常。
- 明确隐私联系渠道、社区举报处理人、事故联系人和维护窗口。

任何一项未完成，都应继续保持内测或受控访问，不开放公网注册。
