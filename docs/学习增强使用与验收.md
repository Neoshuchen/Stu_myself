## 从哪里使用

### 当日实践区（2026-09-10 更新）

学习页通过“动手实践”直达当天任务、各知识点的练习步骤与预期结果。“示例与提示”按需展开，显示课程已有的操作材料、运行方式和讲解；原有流程、任务约束及补充验收要求保存在“学习方法与补充要求”中。

点击“按本日要求整理证据”会将当天任务和验收项填入报告草稿；实际操作、结果和证据位置留空，由学习者填写。已有文字需确认后才替换，生成草稿不会自动提交或完成学习。Python 案件继续使用原有案件记录格式。

此展示方式统一适用于系统路线、个人路线和管理员编辑后的正文，不修改数据库或覆盖课程内容。它复用已有知识详情，并不意味着所有示例都已经是当天综合任务的完整答案；没有知识详情的路线仍展示当天任务和验收项，原有自定义正文可以展开阅读。

## 逐项操作与边界

### 1. 短时学习与接续提示

前置条件：登录并加入路线，从今日页或路线地图进入当前学习日 `/learn/:enrollmentId/:dayNumber`。未来日预习仍为只读，退出路线后需重新加入才能继续写入学习记录。

1. 在“今天先学一小段”选择可用时间。15 分钟建议解释下一个未学知识点并核对例子；30 分钟显示该知识点的实现要求；60 分钟优先处理下一项未完成验收。
2. 点击“打开下一个知识点”，完成实际复现，再标记知识点。所有知识点已经勾选时，入口改为剩余验收或回顾建议。
3. 填写“下次从这里继续”，例如“已复现正常输入，下次补空列表测试”。提示最多 500 字，输入框变更后失焦会触发保存，也可主动保存学习记录。
4. 确认成功提示后再离开；重新打开学习日可读取提示，今日页也会显示接续内容。

可用时间只是当前页面的任务预算，没有倒计时、时长统计、到点奖励或独立学习场次记录。保存提示不代表完成整日；完成仍要求知识点、验收项全部通过且至少有一份证据。

进度 PATCH 按队列提交；新增/删除证据、记录缺口和邀请验证只更新对应列表，不重新加载整份进度。保存失败时当前页面保留草稿，但没有离线存储、跨设备草稿同步或关闭页面后的恢复保证；应联网后重试保存。

### 2. 闭卷三问与间隔复习

入口为 `/review`。仅本人仍参与路线中的已完成学习日进入队列，到期前不能重复提交刷取复习记录。

1. 等待项目进入到期队列。有已审核客观题时，先独立选择全部答案，可附上回忆笔记；页面不会在提交前显示答案或解析。
2. 提交后查看逐题的选择、正确答案和解析，以及本次评级和下次复习时间。评级由服务器计算，前端传入的评级不能覆盖判分。
3. 返回课程复现实验或记录缺口。没有客观题的学习日继续使用“需要重学 / 基本想起 / 熟练掌握”的闭卷自评。

| 调度场景 | 当前规则 |
|---|---|
| 首次复习，存在 `open` 缺口、未填掌握度或掌握度低于 80 | 完成后 1 天 |
| 首次复习，其余情况 | 完成后 3 天 |
| 全错 / 需要重学 | 本次提交后 1 天 |
| 部分正确 / 基本想起 | 上次间隔限制在 3～7 天之间；首次为 3 天 |
| 全对 / 熟练掌握 | 上次间隔的 2 倍，最低 7 天、最高 30 天；首次为 7 天 |

初次调度中的缺口条件按代码只计算 `open`；洞察中“待解决或验证”则同时包含 `open` 和 `verifying`，两处统计用途不同。时间由服务端保存，页面倒计时或本地日期不能改变到期条件。

刷新后可以查看队列项目最近一次作答结果；完整历次记录通过学习导出获取。题目改动会改变版本标记，旧页面会提示刷新重新作答；既有历史快照保留当时题干、选项文字和解析。

### 3. 本地 Python 实验案件

1. 进入下表对应学习日，查看故障描述并下载案件文件。
2. 在本地终端运行 `python 下载的案件文件.py`。文件包含故意出错的函数，第一次出现断言失败是预期现象。
3. 先保存失败输出，定位根因并修改函数，再运行原断言和自己增加的边界样例。
4. 必要时展开“我已尝试，查看线索”和“核对修复思路”。这些是学习提示，没有防查看或防作弊机制。
5. 将案件记录模板填入证据表单，补齐环境、命令、失败输出、根因、修改和通过输出，再手动提交。

案件只依赖 Python 标准库。不要使用 `python -O`，否则断言会被禁用。网站提供下载和证据记录，不运行上传代码，也不会因本地打印“通过”自动勾选验收、结算挑战或完成学习日。

### 4. 讲解接力

前置条件：至少两位朋友加入同一小队，各自先在学习日提交一份自己的证据。

1. 在 `/team` 选择小队，点击“用讲解接力模板发起”。模板仅填写草稿，补充共同主题、说明和截止时间后再发起挑战。
2. 讲解者选择“讲解”，关联自己的证据，写明概念、具体例子和容易误解的地方。
3. 复现者读取分工说明，展开“查看证据”查看正文、链接或附件，独立复现后选择“复现”并提交自己的结果。
4. 有问题时更新自己的分工说明及证据。还可由其他成员承担“测试”或“复核”；一个挑战中每人一项分工、每种角色最多一人。
5. 至少两名成员承担不同角色且所有已提交证据仍存在时，使用合并完成操作结算。已经删除的证据需重新补交。

截止时间限制新增或更新分工；当前完成条件不强制讲解者与复现者组合，也不自动检查反馈是否充分。讲解接力是既有挑战的使用模板，没有独立评分、轮次流转或赛季系统。

提交分工会向本小队成员展示所选证据正文、作品链接和签名附件，不共享其他私人证据或精选标记。退出成员不能再获取挑战详情；已经取得的签名附件链接在到期前仍可使用，默认有效期为 600 秒。

### 5. 知识点 AI 辅导

1. 打开知识卡详情，点击“让 AI 辅导这个知识点”。全局抽屉准备一条新对话，预览待发送标题和正文。
2. 确认当前模型配置，按需要修改或移除上下文。只打开抽屉不会调用供应商。
3. 编辑问题后点击发送。若另一问题尚未发送完成，会提示等待；切换历史会话期间也禁止发送。
4. AI 输出只作为学习参考，是否标记知识点、提交证据和完成当日仍由原学习流程决定。

当前入口截取标题最多 160 字、正文最多 4,000 字，使用所选卡片的摘要、基础知识、机制与练习要求，不自动附带个人复盘、证据和缺口。发送后的片段随消息存入 MySQL，并可能在后续上下文中再次发送给所选供应商。

历史会话仅接受最后一次选择的加载结果；新建对话或进入模型配置页会废止旧加载结果。保存长期模型配置需独立 Fernet 主密钥；临时 Key 仅保留在当前页面。具体生命周期见 [隐私基线](./隐私与社区治理基线.md)。

### 6. 私人成果展柜与分享草稿

1. 在每日学习页的证据列表点击“选入私人成果展柜”，然后打开 `/insights` 的能力图谱查看精选作品。
2. 展柜展示证据文字、链接、附件和所属学习日复盘。移出展柜只取消精选，不删除原证据；退出路线的历史证据仍可精选或移出。
3. 点击“整理为项目分享草稿”，进入 `/community/new`。草稿包含作品标题、路线与日编号、证据文字、作品链接和当日复盘；纯链接作品也保留 URL。
4. 检查并编辑正文后手动发布。私有附件及其签名地址不会自动复制，想发布图片时需要在社区编辑页另行选择。

展柜只对本人展示，没有公开展柜主页。草稿通过浏览器导航状态传递，尚未写入社区；重新打开同一历史页面可能再次回填原始草稿，但未发布编辑不保证恢复，不是服务器草稿箱。

## 数据与接口对照

接口均以 `/api/` 开头，除健康检查和签名媒体等既有例外外需要登录。下表用于定位现有代码，不表示客户端可以跳过归属、路线状态或完成条件。

| 行为 | 方法与路径 | 关键字段 / 结果 |
|---|---|---|
| 保存学习进度 | `PATCH /api/progress/{id}/` | `resume_note`、`reflection`、`recall_score`、两组布尔检查数组；子记录另行提交 |
| 复习队列 | `GET /api/reviews/` | `reviews.due`、`upcoming`、题目 `quiz`、`latest_results` 及成长信息 |
| 提交客观复习 | `POST /api/reviews/` | `progress`、`answers`、`quiz_token`、可选 `note`；返回判分记录及新队列 |
| 提交无题自评 | `POST /api/reviews/` | `progress`、`rating`、可选 `note`；评级为 `forgot`、`unsure`、`mastered` |
| 新增证据 / 缺口 | `POST /api/evidence/`、`POST /api/gaps/` | 引用本人的有效 `progress`；证据带文件时使用 multipart |
| 申请缺口验证 | `POST /api/gaps/{id}/request-verification/` | `resolution`，可指定 `group`；需要证据及可验证的朋友 |
| 提交接力分工 | `POST /api/team-challenges/{id}/contribute/` | `role`、本人 `evidence`、`summary`；已有分工会更新 |
| 切换精选 | `POST /api/evidence/{id}/feature/` | `is_featured` 必须为真正的 JSON 布尔值 |
| 查看展柜 | `GET /api/insights/` | `showcase` 仅返回本人精选证据及所属学习日信息 |
| 导出学习记录 | `GET /api/insights/export/?type=json` 或 `type=markdown` | 返回 `filename`、`mime`、字符串 `content`，前端再生成下载文件 |

客观作答的 `answers` 是“题目 ID → 从 0 开始的选项索引”的 JSON 对象，必须完整匹配本次返回的全部题目，不接受布尔值、越界索引或额外题目。`quiz_token` 是题目内容的版本哈希，不是登录凭证或答题会话令牌；客户端不能写入 `quiz_results`。

| 持久字段 | 模型 | 默认值与用途 |
|---|---|---|
| `resume_note` | `DayProgress` | 空字符串，最多 500 字；下次继续的提示 |
| `quiz_results` | `ReviewAttempt` | 空数组；逐题 `id/prompt/selected/expected/correct/explanation` 快照，选择与正确答案保存为文字 |
| `is_featured` | `Evidence` | `false`；控制本人展柜是否收录，不改变公开性 |

### 导出范围

JSON 包含用户名、导出时间及本人所有报名记录（含退出路线）的已有学习日；日记录包含状态、掌握度、复盘、接续提示、证据、缺口和全部复习历史。证据包括类型、标题、正文、作品链接和精选状态；复习历史包括评级、笔记、时间、间隔及当时的题目解析。

Markdown 是便于阅读的摘要：包含接续提示、证据标题与精选标记、缺口标题、历次复习与解析，**不会像 JSON 一样保留完整证据正文、作品 URL 或缺口详情**。需要完整结构化学习记录时选择 JSON。

两种导出都不打包附件二进制，不包含 AI 对话、API Key、小队完整历史或社区帖子的全量备份；也没有对应的学习记录导入恢复功能。生产灾难恢复应使用数据库与媒体备份。

|---|---|---|---|
| Python 基础 | Day 2：变量与对象 | 3 | 原始清单被共享引用意外修改 |
| Python 基础 | Day 3：数字与运算 | 3 | float 转换导致十进制精度丢失 |
| Python 基础 | Day 6：条件分支与 for 循环 | 3 | range 未包含终点 |
| 爬虫基础 | Day 2：HTTP 请求 | 3 | — |
| Git 全流程 | Day 1：可靠提交 | 3 | — |

题目、解析与案件由 `backend/learning/study/practice.py` 统一维护，按路线 slug、日编号和 `core_knowledge` 精确匹配。管理员改编主题后，旧题不会继续挂在不匹配的课程上。题目版本标记随题干、选项、答案或解析变化，旧页面提交会被拒绝并提示刷新。没有匹配题目的学习日保留原有闭卷自评流程。

首版复用固定三问，没有自动生成题目、轮换题库或代码执行服务。实验的本地断言只用于帮助复现，整日完成仍依赖原有知识点、验收项与证据门禁。

### 维护题目与案件

维护入口是 [`practice.py`](../backend/learning/study/practice.py)。先核对实际课程 slug、日编号和 `core_knowledge`，再调整对应题目与案件；旧 slug 中的 `60d` 是稳定标识，不代表课程仍有 60 天。每道题保留唯一 ID、题干、选项、合法答案索引和解析。

题目、案件来自代码，课程正文来自数据库；只有三项匹配时才展示练习。Fork、自建路线或管理员修改主题不会自动继承固定题库。新增覆盖应同时验证提交前不泄露答案、服务端判分、旧版本拒绝，以及案件原始失败和修复后通过；不要直接把参考答案当成自动验收结果。

维护调用链：`PlanDaySerializer` 提供实验信息，`review_center → review_quiz` 提供题目，`ReviewAttemptSerializer → grade_review → record_review` 校验、判分并保存，`LearningExportView` 读取历史快照。共享规则应在这些入口统一维护。

## 升级

在配置好目标数据库的后端环境执行：

```powershell
python manage.py migrate
```

迁移 `0017_learning_practice_and_showcase` 仅增加三个字段：`DayProgress.resume_note`、`ReviewAttempt.quiz_results`、`Evidence.is_featured`。已有记录分别获得空提示、空答案快照和未精选状态。随后重新构建前端并按现有部署手册启动服务。不需要重新导入或覆盖课程 JSON。

发布前备份目标数据库和媒体；迁移后运行 `python manage.py showmigrations learning` 确认 `0017` 已勾选，再更新前端。既有数据库回滚到 `0016` 会删除这三个字段及其新数据，不能把反向迁移当作无损回滚。本地 2026-09-05 的迁移结果不代表其他环境已升级。

## 常见问题与人工验收

| 现象 | 先核对什么 | 预期处理 |
|---|---|---|
| 没有闭卷三问或实验入口 | 是否是首批覆盖主题，数据库主题是否与代码完全匹配 | 无覆盖时走原自评/课程实验，不强制挂错题 |
| 刚完成就想复习，提交被拒绝 | 服务端到期时间、报名状态 | 等待到期；不要为验收手动篡改真实学习记录 |
| 题目已更新或选项无效 | 页面是否长期未刷新 | 刷新队列，完整重新选择后提交 |
| 记录缺口后保存仍失败 | 网络状态与页面错误 | 保留当前页面，重试保存；不要刷新丢弃尚未保存文字 |
| 无法邀请缺口验证 | 是否有证据、解决过程及同队朋友 | 补齐后申请，由朋友通过或退回 |
| 接力不能合并 | 是否有两个不同角色、证据是否已删除 | 阅读返回原因并补交证据；超期不能更新分工 |
| AI 不可用 / 配置不可保存 | 站点 AI 开关、凭据主密钥、模型配置 | 管理员修正配置后重试；具体错误见部署手册 |
| 展柜作品未出现在社区 | 是否只打开了分享草稿 | 审核正文后点击发布 |
| 附件链接过期 | 签名时间及当前业务访问权限 | 重新打开有权限的页面获取新地址，不手工拼 media 路径 |

人工验收至少走一遍“编辑接续 → 提交证据/缺口 → 刷新确认”“完成 → 到期作答 → 导出”“两位成员讲解与复现 → 合并”“精选 → 草稿审核 → 发布”。生产 AI 验收另用低权限测试配置执行真实请求，观察费用、错误和删除流程；自动化模拟结果不能替代这一项。

- 周成果卡保留个人总完成天数，契约是否兑现仅按该契约的报名路线计算，与小队仪表盘一致。
