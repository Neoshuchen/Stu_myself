# 第四阶段：上线前规模化能力开发规划

> 状态：规模化产品能力仍为规划；截至 2026-08-28，生产基础代码、全局 AI 和关键浏览器回归已经完成，真实服务器验证项与本阶段的数据量触发条件仍未满足。

## 1. 阶段目标

第四阶段解决的不是单个学习功能，而是网站公开运营后的规模化问题：用户如何找到适合自己的内容、管理员如何看见整体运行状况、社区如何在内容增长后保持安全与可信。

本阶段包含三项能力：

1. 学习路线与内容推荐
2. 匿名学习生态数据分析
3. 社区自动风控与治理辅助

不在本阶段引入实时聊天、私信、积分商城或付费课程。

## 2. 开发前置条件

只有满足以下条件后才启动对应模块：

- 至少有 100 名有效学习用户或 10 条持续维护的公开路线。
- 已积累不少于 30 天的学习进度、路线反馈和社区行为数据。
- 已发布隐私政策、社区规范、数据导出与账号删除说明。
- 已完成数据库自动备份、错误监控、日志脱敏和恢复演练。
- 管理员审核与举报处理已有稳定负责人和响应规则。

如果没有达到这些条件，继续采用人工精选和现有管理员审核，避免伪精确算法。

## 3. 智能推荐

### 3.1 第一版目标

使用可解释的规则排序，不接入复杂机器学习：

- 用户选择的学习方向与路线标签匹配。
- 用户可投入时间与路线预计时长匹配。
- 用户历史反馈中的难度感受与路线难度匹配。
- 路线完成率、7 日留存率、内容清晰度和最近维护时间共同计分。
- 已经加入、完成或明确不感兴趣的路线降低优先级。

每条推荐必须显示原因，例如：“适合每天 60 分钟学习，且与你完成的 Python 基础路线衔接”。

### 3.2 数据要求

- 路线主题标签、前置能力、预计投入时间。
- 匿名化的加入、开始、完成和退出位置。
- 路线反馈中的难度、清晰度与实践性。
- 用户主动设置的学习目标，不从帖子内容推测敏感偏好。

### 3.3 验收标准

- 推荐接口 P95 响应不超过 300ms。
- 用户可关闭个性化推荐并查看通用精选路线。
- 推荐原因可解释，不产生仅由热度驱动的马太效应。
- 新路线保留探索曝光位置。

## 4. 匿名学习生态数据

### 4.1 公共指标

- 各路线加入人数、真实开始率、7 日留存率、完成率。
- 每个学习日的到达率、完成率和中断率。
- 匿名聚合的高频知识缺口。
- 路线难度反馈分布和最近维护时间。
- 社区问题响应时间和已解决比例。

### 4.2 隐私规则

- 少于 10 人的数据分组不公开。
- 不公开单个用户的学习时间、失败记录、知识缺口和活跃轨迹。
- 管理员导出数据默认去除用户名、邮箱、IP、正文和附件地址。
- 数据统计使用独立的聚合表，避免公开接口直接查询个人明细。
- 明确数据保留周期和用户删除后的聚合处理方式。

### 4.3 技术方案

初期使用 Django 定时管理命令按日写入聚合表，由 MySQL 承载；只有在数据量和查询延迟证明不足时，再考虑队列、数仓或独立分析服务。

## 5. 自动风控

自动风控只辅助管理员，不自动永久封禁用户。

### 5.1 检测范围

- 短时间重复发布相同或高度相似内容。
- 高频发帖、评论、点赞和举报。
- 外链、联系方式、Token、密码和疑似隐私信息。
- 被多名不同用户举报的内容。
- 新账号批量发布广告或灌水。

### 5.2 处置等级

1. 提交前提醒：发现疑似 Token、密码或隐私信息，要求用户确认。
2. 限速：对异常高频请求返回明确的冷却时间。
3. 待审核：高风险内容仅作者和管理员可见。
4. 人工处置：管理员决定恢复、删除或限制账号。

每次自动判定需保存规则编号和原因，支持管理员复核与撤销。

### 5.3 不采用的方案

- 不对技术关键词做简单黑名单封禁。
- 不根据单次举报自动删除内容。
- 不把公益贡献积分当作可信度的唯一依据。
- 不在没有申诉机制时自动封号。

## 7. 推荐开发顺序

1. 上线安全、备份、监控和隐私文档。
2. 匿名聚合数据模型与管理员运营面板。
3. 可解释的规则推荐与用户关闭开关。
4. API 限速、隐私信息提醒和重复内容检测。
5. 待审核队列、处置日志和申诉机制。
6. 根据真实误报率再决定是否引入更复杂模型。

## 8. 完成定义

- 推荐、统计和风控均有自动化测试、权限测试与回滚方案。
- 用户可以知道推荐依据、关闭推荐、导出和删除个人数据。
- 管理员可以解释并撤销任何自动风控处置。
- 公开统计无法反推出具体用户。
- 备份恢复、异常告警和内容申诉至少完成一次演练。
