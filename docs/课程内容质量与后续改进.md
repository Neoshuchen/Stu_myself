# 课程内容质量与后续改进

> 核对日期：2026-08-28  
> 文档性质：当前课程事实、仍有效的质量边界和后续优先级。历史审计过程与已经修复的旧统计不再保留。

## 当前基线

- 唯一版本化课程源是 `backend/data/system_roadmaps.v2.json`，`schema_version=2`、`content_version=5`。
- 目录包含 6 条系统路线、482 个连续学习日和 482 张知识卡：一条 182 日加速路线及 Python、爬虫、JavaScript、Android、iOS 五条 60 日路线。
- 运行时权威来源是 MySQL；JSON 只由 `import_curated_roadmaps` 校验并幂等导入。管理员人工编辑过的学习日默认不会被再次导入覆盖。
- 当前导入和测试会校验路线分类、连续日编号、必填内容、公开资料地址及内部来源泄漏。学习页面的完成门禁仍要求全部检查项和至少一份证据。

## 已完成治理

- 课程正文已统一到内容版本 5，并保持原路线标识及用户进度关联。
- 已删除课程输出中的内部资料地址，学习者资料只允许公开来源。
- 知识卡具备概念、机制、常见错误、最小实验、参考代码、预期结果、练习与掌握标准等结构。
- 对采集和逆向主题明确限定本人资产、专用靶场或已授权样本，不把 `robots.txt`、可访问页面或技术可行为视作授权。
- 课程导入、管理员正文保护和强制覆盖路径已有自动化测试。

## 仍需解决的质量边界

1. **实验资产不完整**：仓库没有课程专用 APK、iOS App、本地 HTTP 靶场或 Babel 实验工程；当前只包含应用自身的前后端依赖清单。涉及真实目标的学习日必须由学习者提供合法环境，不能宣称开箱即复现。
2. **依赖仍分散在正文**：当前目录仍包含 Babel、pytest 等工具说明以及 92 处 `/path/to` 示例路径。上线固定实验前，应为每条路线提供独立、锁定版本的实验依赖和预检命令。
3. **掌握度主要依赖自评与同伴证据**：间隔复习、证据、缺口和朋友验证已经形成闭环，但尚无覆盖所有代码型任务的客观自动判题。
4. **内容变更缺少版本差异和回滚**：`content_edited_at` 可以保护人工修改，却不能向在学用户展示版本差异，也没有课程级一键回滚。
5. **移动端结论需要真实设备复核**：Android/iOS 路线涉及系统版本、签名、设备状态和工具版本差异，不能仅凭静态课件保证每个实验成立。

## 后续优先级

| 优先级 | 工作 | 完成标准 |
|---|---|---|
| P0 | 固定授权实验资产与路线级依赖 | 本地 HTTP/JS 样例及授权移动端样本有版本、校验和、安装步骤和标准输出 |
| P0 | 内容版本差异与回滚 | 管理员可查看操作者、变更字段和版本，并可恢复上一稳定版本 |
| P1 | 少量高价值客观测验 | 优先覆盖可确定判断的 Python、HTTP、JS 输出和错误路径，不为所有主题强造判题器 |
| P1 | 课程质量看板 | 能看到卡点日、退出位置、重复缺口和反馈处理状态，不公开个人明细 |
| P2 | Markdown/AI 路线生成 | 只生成私有草稿，复用现有配置、结构校验和管理员审核，不直接发布 |

## 不采用的扩充

- 不用新增更多长路线掩盖实验不可复现的问题。
- 不为一份路线再建第二套课程模型、导入状态机或发布流程。
- 不执行模型生成的代码，也不让 AI 结果绕过人工确认和管理员审核。
- 不使用登录积分、全站排行榜或打卡次数代表掌握程度。
